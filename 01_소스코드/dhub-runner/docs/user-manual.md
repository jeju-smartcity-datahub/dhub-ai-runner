## 1. 화면 구성

브라우저에서 관리자가 알려준 주소(기본 `http://localhost:8080`)를 엽니다.

| 영역 | 내용 |
|---|---|
| 왼쪽 메뉴 | 홈, 가져오기, 운영, 카탈로그, 등록한 컬렉션 목록, 시크릿, API 문서 |
| 위쪽 막대 | 지금 위치(홈 / 컬렉션 / 대상), 오른쪽 끝의 테마 전환(어둡게·밝게) |
| 본문 | 고른 화면 |

- **컬렉션**은 D.Hub for AI에서 내보낸 묶음 하나입니다. 파이프라인, 에이전트, 데이터셋, 코드, 커넥터, 시크릿 목록이 들어 있습니다.
- **데이터셋**은 파이프라인이 읽고 쓰는 Delta 테이블입니다. 버전이 쌓이므로 예전 시점의 데이터도 볼 수 있습니다.
- 상태는 색 배지로 보입니다: 완료(초록), 실행 중·대기(파랑), 실패·중지됨(빨강), 취소됨·스케줄 일시정지·설정 필요(노랑).

## 2. 컬렉션 가져오기

1. D.Hub for AI 포탈에서 컬렉션을 **내보내기**해 ZIP을 받습니다.
2. 러너의 **가져오기**에서 ZIP을 고릅니다. 컬렉션 이름은 파일 이름으로 채워지며 바꿀 수 있습니다(영문, 숫자, `_`, `-`, `.`).
3. **가져오기**를 누르면 결과가 나옵니다.
   - **가져온 리소스**: 러너가 실행할 수 있는 것
   - **건너뛴 리소스**: 폴더, 대시보드, 지식처럼 러너가 실행하지 않는 것
   - **초기 데이터**: 처음 실행할 때 데이터셋에 적재할 파일
   - **입력이 필요한 시크릿**: 내보내기에는 값이 없으므로 직접 넣어야 하는 것 ([3. 시크릿 입력](#3-시크릿-입력))

같은 이름의 컬렉션을 ZIP으로 다시 올리려면 **같은 이름의 컬렉션을 ZIP으로 바꾸기**를 켭니다.
파일 몇 개만 더하려면 컬렉션 화면의 **리소스 추가**에서 리소스 JSON, 코드 본문(`<코드 이름>.py`/`.sql`), 데이터(`<데이터셋>.csv`/`.json`/`.parquet`)를 올립니다.

컬렉션 화면의 **삭제**는 컬렉션과 그 테이블, 실행 이력, 대화 세션, 시크릿, 카탈로그 정보까지 지웁니다. 되돌릴 수 없습니다.

## 3. 시크릿 입력

API 키, 접속 주소처럼 내보내기에 없는 값은 러너에 직접 넣습니다. 넣은 값은 암호화해 저장되며 **다시 보여주지 않고**, 어디서 오는지만(컬렉션 / 공용 / 값 없음) 보여줍니다.

| 어디에 | 언제 |
|---|---|
| 왼쪽 메뉴 **시크릿** (공용) | 여러 컬렉션이 함께 쓰는 값. 예: LLM 엔드포인트 `dhub_llm/base_url`, `dhub_llm/api_key` |
| 컬렉션 화면의 **시크릿** 탭 | 그 컬렉션만 쓰는 값. 공용 값보다 먼저 쓰입니다 |

- 표의 **새 값** 칸에 입력하고 **저장**합니다. 값을 지우려면 공백 한 칸을 넣고 저장합니다.
- 여러 개를 한 번에 넣으려면 **여러 개 한 번에 입력**에 한 줄에 하나씩 `시크릿/키=값`을 붙여 넣습니다. `#`로 시작하는 줄은 무시하고, 값이 비면 그 키를 지웁니다.

컬렉션 화면 위에 "값이 없는 시크릿" 경고가 보이면 그 값을 넣어야 파이프라인이나 에이전트가 돕니다.

## 4. 파이프라인 실행

컬렉션 화면의 **파이프라인** 표에서 **실행**을 누릅니다. 이름을 누르면 상세 화면이 열립니다.

| 항목 | 뜻 |
|---|---|
| 스텝 | 실행 순서대로 각 스텝의 종류(코드, transform), 입력·출력 데이터셋, 마지막 상태. 실패한 스텝은 **오류 보기**로 원인을 봅니다 |
| 실행 이력 | 최근 실행 20개의 상태, 시작·종료 시각, 오류 |
| 정의 | 파이프라인 JSON (자격증명은 가림) |

- **중지**: 실행 중인 파이프라인을 멈춥니다. 진행 중인 스텝은 끝까지 돌고 다음 스텝 전에 멈춥니다.
- **스케줄 정지 / 재개**: 예약 실행(`options.schedule`)만 멈추거나 다시 켭니다. 직접 실행은 계속 됩니다.
- **체크포인트 초기화**: 스텝이 기억한 읽기 위치(CDC 오프셋)를 지웁니다. 다음 실행은 입력 데이터셋을 처음부터 읽습니다.
- 같은 파이프라인은 한 번에 하나만 돕니다. 실행 중에 다시 누르면 진행 중인 실행을 그대로 보여줍니다.
- 실행할 수 없는 파이프라인(러너가 지원하지 않는 기능을 씀)은 빨간 상자에 이유가 나오고 **실행** 버튼이 꺼집니다.

## 5. 운영 화면

왼쪽 메뉴 **운영**은 모든 컬렉션의 파이프라인과 에이전트를 한 화면에 모읍니다. 위쪽 숫자는 실행 중인 파이프라인, 켜진·멈춘 스케줄, 켜진·중지된 에이전트 수입니다.
여기서 바로 실행·중지, 스케줄 정지·재개, 에이전트 시작·중지를 할 수 있으며 상태는 자동으로 새로 고쳐집니다.

## 6. 데이터 카탈로그

왼쪽 메뉴 **카탈로그**는 모든 컬렉션의 데이터셋을 찾는 곳입니다.

> 카탈로그 검색, 문서·태그, 저장한 쿼리는 관리자가 Postgres를 연결했을 때만 쓸 수 있습니다. 연결이 없으면 카탈로그 화면에 안내가 나오며, 데이터셋은 컬렉션 화면에서 볼 수 있습니다.

### 검색

검색창에 단어를 넣고 Enter를 누릅니다. 여러 단어는 **모두** 맞아야 합니다. 이름, 별칭, 설명, 컬럼 이름·설명·메모, 태그, 소유자, 문서에서 찾으며, 이름에 맞은 것이 먼저 나옵니다.

한 필드에서만 찾으려면 앞에 필드 이름을 붙입니다.

| 쓰는 법 | 찾는 것 |
|---|---|
| `tag:매출` | 태그에 "매출"이 들어간 데이터셋 |
| `col:customer_id` | 그 이름의 컬럼이 있는 데이터셋 |
| `type:datetime` | 그 타입의 컬럼이 있는 데이터셋 |
| `owner:데이터팀` | 소유자 |
| `collection:quickstart` | 컬렉션 이름이나 별칭 |
| `col:"order id"` | 값에 공백이 있을 때 큰따옴표 |

예: `주문 tag:대시보드` → 대시보드 태그가 붙은 데이터셋 중 "주문"이 들어간 것.

### 거르기와 정렬

- 왼쪽 상자의 **컬렉션, 데이터(있음·아직 없음), 태그, 소유자**를 누르면 결과를 거릅니다. 옆 숫자는 지금 검색어에 맞는 개수입니다. 다시 누르거나 위쪽 칩의 ✕를 누르면 풀립니다.
- 검색창 오른쪽에서 관련도, 이름, 최근 변경, 행 수, 크기, 버전, 컬렉션 순으로 정렬합니다.
- 위쪽 숫자는 결과 전체의 데이터셋 수, 데이터가 있는 수, 전체 행, 전체 크기, 컬렉션 수입니다.
- 결과 카드에는 별칭과 이름, 설명, 컬렉션, 태그, 검색어에 맞은 컬럼, 행 수·크기·버전·마지막 변경·소유자가 보입니다.

### 최신 상태로 맞추기

카탈로그는 파이프라인 실행이 끝날 때와 1분마다 저절로 바뀝니다. 바로 맞추려면 오른쪽 위 **동기화**를 누르세요.

## 7. 데이터셋 화면

카탈로그 결과나 컬렉션 화면의 데이터셋 이름을 누르면 열립니다. 위쪽에 행 수, 크기, 파일 수, 버전, 마지막 변경이 보입니다.

| 탭 | 할 수 있는 것 |
|---|---|
| **개요** | 문서 읽기, 속성(위치, 파티션, 테이블 속성, 만든·바뀐 시각) 보기, 오른쪽에서 **소유자·태그·문서**를 고쳐 저장 |
| **스키마** | 컬럼마다 타입, null 허용, 설명, null 수(비율), 최소·최대. **컬럼 찾기**로 거르고, 컬럼 **메모**를 적어 **메모 저장** |
| **데이터** | 행 보기. **버전**을 고르면 그 시점의 데이터를 봅니다. **CSV**, **Parquet**로 내려받기 |
| **이력** | 커밋마다 버전, 시각, 작업(쓰기·삭제 등), 모드(Append·Overwrite), 추가 행, 파일 수. **이 버전 보기**로 그 시점 데이터 열기 |
| **계보** | 상위 데이터셋 → 쓰는 스텝 → 이 데이터셋 → 읽는 스텝 → 하위 데이터셋. 상자를 누르면 그 데이터셋이나 파이프라인으로 이동 |
| **SQL** | 이 컬렉션의 데이터셋을 SQL로 조회 ([8. SQL로 조회하기](#8-sql로-조회하기)) |

- 태그는 D.Hub for AI 정의에 붙은 것과 여기서 붙인 것이 함께 보입니다. 여기서는 직접 붙인 태그만 고칠 수 있습니다.
- 문서·태그·메모는 다시 가져오기나 동기화로 지워지지 않습니다. 컬렉션을 삭제하면 함께 지워집니다.
- **다시 읽기**는 이 컬렉션의 테이블 정보를 지금 다시 읽습니다.
- "데이터 없음"은 아직 어떤 파이프라인도 이 데이터셋을 쓰지 않았다는 뜻입니다. 쓰는 파이프라인을 실행하세요.

## 8. SQL로 조회하기

데이터셋 화면의 **SQL** 탭에서 이 컬렉션의 데이터셋을 조회합니다.

```sql
SELECT status, COUNT(*) AS orders, SUM(amount) AS amount
FROM "orders_raw"
GROUP BY status
ORDER BY amount DESC
```

- **실행** 또는 Ctrl/⌘ + Enter. 결과 위에 행 수, 걸린 시간, 읽은 테이블이 나옵니다.
- `SELECT`(또는 `WITH ... SELECT`) 한 문장만 됩니다. 읽기 전용이라 데이터를 바꾸지 않습니다.
- 최대 1000행을 보여줍니다. 더 많으면 "1000행에서 잘림"이 붙으니 집계하거나 조건을 거세요.
- 문법은 Polars SQL(PostgreSQL에 가까움)입니다. 테이블·컬럼 이름은 큰따옴표로 감싸고 대소문자를 구분합니다. 조인, 서브쿼리, CTE, 윈도 함수를 쓸 수 있습니다.
- **저장할 이름**을 넣고 **저장**하면 오른쪽 **저장한 쿼리**에 남습니다. 컬렉션의 모든 데이터셋 화면에서 함께 보이며, 누르면 불러와 실행합니다. 불러온 쿼리를 고쳐 저장하면 덮어씁니다.

## 9. 에이전트와 대화하기

컬렉션 화면의 에이전트 카드에서 **대화**를 누릅니다.

1. 아래 입력창에 메시지를 쓰고 **보내기**를 누릅니다.
2. 에이전트가 툴을 쓰면 보라색 줄로 어떤 툴을 어떤 값으로 불렀는지 보입니다.
3. 승인이 필요한 동작(예: 쿠폰 발송)은 노란 상자에 내용과 함께 **승인 / 거부** 버튼이 나옵니다. 고르면 에이전트가 이어서 답합니다.

- 왼쪽 **세션** 목록에서 지난 대화를 다시 열거나 휴지통으로 지웁니다. **새 대화**는 새 세션을 시작합니다.
- **중지**된 에이전트는 대화를 받지 않습니다. **시작**을 누르면 다시 됩니다.
- 데이터셋 조회 툴(text2sql)을 가진 에이전트는 컬렉션의 데이터셋을 SQL로 조회해 답합니다. 카탈로그의 컬럼 설명이 많을수록 정확해집니다.

## 10. 챗봇 공유와 임베드

에이전트 화면의 **챗봇 열기**는 대화만 있는 화면(`/chat`)을 새 탭으로 엽니다. 답을 표·코드·목록으로 보여주고 툴 실행을 단계별로 보여줍니다.

| 주소 | 뜻 |
|---|---|
| `/chat?collection=<컬렉션>&agent=<에이전트>` | 그 에이전트로 고정 |
| `…&embed=1` | 목록 없이 대화만 (다른 페이지에 iframe으로 넣을 때) |
| `…&session=<id>` | 지난 대화 열기 |
| `…&theme=light` 또는 `dark` | 테마 고정 |

```html
<iframe src="https://runner.example.com/chat?collection=quickstart&agent=sales_assistant&embed=1"
        style="width:420px;height:640px;border:0"></iframe>
```

러너에는 로그인이 없으므로, 밖에 공유하기 전에 관리자에게 접근 제한을 확인하세요.

## 11. 자주 묻는 질문

**파이프라인이 "secret … is not set"으로 실패합니다.**
그 시크릿 값이 없습니다. 오류에 나온 `시크릿/키`를 공용 시크릿이나 컬렉션 시크릿 탭에서 넣고 다시 실행하세요.

**실행 버튼이 꺼져 있습니다.**
파이프라인 아래 빨간 상자의 이유를 보세요. 러너가 지원하지 않는 기능(온톨로지, Kafka, Spark 등)을 쓰는 파이프라인은 실행할 수 없습니다.

**데이터셋이 "데이터 없음"입니다.**
아직 그 데이터셋에 쓴 실행이 없습니다. 계보 탭이나 개요의 안내에서 쓰는 파이프라인을 찾아 실행하세요.

**방금 실행했는데 카탈로그 숫자가 그대로입니다.**
최대 1분 안에 바뀝니다. 바로 보려면 카탈로그의 **동기화**나 데이터셋의 **다시 읽기**를 누르세요.

**SQL이 "only one SELECT … is allowed"라고 합니다.**
한 번에 `SELECT` 한 문장만 됩니다. 끝의 세미콜론 뒤에 다른 문장이 있거나 `INSERT`, `DROP` 같은 문장은 실행하지 않습니다.

**SQL에서 테이블을 찾지 못합니다.**
이름을 `"orders_raw"`처럼 큰따옴표로 감싸고, 그 데이터셋에 데이터가 있는지 확인하세요. 오류 아래에 데이터가 있는 테이블 목록이 나옵니다.

**카탈로그에 "Postgres가 필요합니다"가 나옵니다.**
이 러너는 Postgres 없이 돌고 있습니다. 데이터셋 화면은 쓸 수 있지만 검색·문서·태그·저장한 쿼리는 관리자가 Postgres를 연결해야 합니다.

**API로 같은 일을 하고 싶습니다.**
왼쪽 메뉴 **API 문서**(`/api/docs`)에서 모든 API와 요청·응답 형식을 보고 바로 호출해 볼 수 있습니다.
